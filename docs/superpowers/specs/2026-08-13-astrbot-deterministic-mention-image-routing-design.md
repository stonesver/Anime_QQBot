# AstrBot 可配置确定性 @命令与图片直发设计

日期：2026-08-13

## 1. 背景

当前 AstrBot 自然语言入口把 Anime Core 的只读结果序列化为文本，再由 MiniMax 组织最终
回答。固定 `/番剧` 命令仍使用原有文本或图片呈现。

这带来两个可改进点：

- `@机器人 今天播什么` 等语义固定的短语仍会调用 MiniMax；
- 自然语言 Tool 即使查询到了可用的排期图或番剧卡片，也只把文字交给 MiniMax。

本设计在不扩大模型权限的前提下，让确定性短语完全绕过 MiniMax，并让其余自然语言查询
在命中已有图片呈现时直接发送图片、停止 Agent，避免重复正文和不必要的第二轮模型输出。

## 2. 目标

- 群内明确 `@机器人` 后，严格匹配的固定短语由本地解析器和 Anime Core 直接执行；
- 确定性短语不发起 MiniMax 请求，沿用现有文字、排期图和番剧卡片；
- 未匹配的 `@机器人` 消息按每群 LLM 模式进入 AstrBot 原生 LLM 链路或返回本地帮助；
- LLM Tool 查询得到本地图片 Reply 时直接发送图片，并停止当前 Agent；
- 图片不可用或发送失败时安全退回当前文本 Tool 流程；
- 机器人管理者可以配置全局统一的安全匹配词；
- 每个群可以配置 LLM 模式、是否启用确定性 `@` 短语和是否优先发送图片；
- `/番剧` 固定命令和通知保持现有语义。

## 3. 非目标

- 不用 MiniMax 或另一个模型判断消息是否属于固定命令；
- 不做模糊意图分类、同义句生成、向量检索或长期记忆；
- 不让 LLM 执行订阅、退订或设置修改；
- 不让 Tool 发送远程 URL 图片，只允许现有缓存根目录中的本地 PNG；
- 不为图片再生成 MiniMax 说明文字；
- 不开放任意正则表达式、回复模板或每群独立匹配词；
- 不修改主动通知、限频或熔断规则。

## 4. 产品规则

### 4.1 确定性优先

群内明确 `@机器人` 时，先运行锚定的固定短语解析器。匹配成功后本地执行并停止事件传播，
不会创建 MiniMax 请求。匹配失败时返回“未匹配”，由 AstrBot 继续处理，不再发送
`not a supported mention command` 或其他错误提示。

系统提供以下内置默认短语：

- 今日：`今天播什么`、`今天有什么`、`今天有什么番`、`今日番剧`；
- 本周：`本周播什么`、`本周有什么`、`本周有什么番`、`本周番剧`；
- 搜索：`搜番 <名称>`、`搜索 <名称>`、`找番 <名称>`；
- 详情：`详情 <名称或编号>`、`看 <名称或编号>`；
- 下一集：`下次 <名称或编号>`；
- 资源：`资源详情 <名称或编号> [集数]`；
- 个人查询：`我的订阅`、`我的追番`；
- 写命令：`追番/订阅 <名称或编号>`、`退订/取消订阅 <名称或编号>`；
- 候选编号：在现有候选会话范围内回复 `1` 至 `20`。

解析继续使用完整匹配，不把“你觉得胆大党好看吗”之类开放式问题误判为固定命令。

机器人管理页提供一套全局统一的匹配词配置。无参数动作使用精确短语列表；带参数动作使用
前缀列表，参数必须出现在前缀后的非空文本中。配置只接受普通文本，不接受正则表达式。
保存时统一空白、去重并执行冲突校验；同一个规范化短语或前缀不能属于两个动作。

数据库没有策略行时使用内置默认值。管理者第一次保存后写入全局单例策略；恢复默认会把
单例更新为代码中的内置集合并保留递增版本号，避免旧页面用过期版本覆盖新配置。各群只
配置是否启用确定性短语，不维护不同叫法。

### 4.2 确定性呈现

本地命令复用现有 `EventAdapter`：

- 今日和本周在渲染成功时发送排期图片；
- 唯一搜索、详情和下一集在真实海报可用时发送番剧卡片；
- 多候选、季度、资源详情、订阅列表及图片失败场景使用现有确定性文本；
- 订阅和退订沿用现有写入、身份、候选会话和权限边界。

这条路径不注册或调用 LLM Tool，也不进入 `LLMPolicyGuard`。

### 4.3 自然语言 Tool 图片直发

未匹配固定短语的消息可以由 MiniMax 调用 `anime_readonly_query`。Tool 使用带现有
`CardReplyFactory` 和 `ScheduleReplyFactory` 的 `EventAdapter`，保留内部 `Reply`，同时生成
给模型使用的只读文本结果。

当 `Reply` 包含通过本地缓存校验的 PNG 时：

1. Tool 通过当前 AstrBot 事件直接发送图片 MessageChain；
2. 图片发送成功后设置当前事件的 Agent 停止信号；
3. 当前 Agent 不再生成最终 MiniMax 正文；
4. Tool 的内部状态标记为成功，策略守卫不生成失败提示。

图片发送失败时不停止 Agent；Tool 返回同一次查询产生的文本 fallback，让 MiniMax 按现有
规则回答。Tool 不因图片失败再次查询数据库或重复渲染。

### 4.4 MiniMax 消耗

- `/番剧` 和确定性 `@` 短语：零 MiniMax 调用；
- LLM 模式为 `disabled`：未匹配短语返回本地能力提示，零 MiniMax 调用；
- LLM 模式为 `anime_only`：番剧自然语言使用 Tool，未调用 Tool 的回答由代码替换为番剧帮助；
- 自然语言查询且命中图片：只保留识别并调用 Tool 的模型轮次，图片成功后停止后续正文；
- 自然语言查询且只有文本：保持当前 Tool 结果加最终回答流程；
- LLM 模式为 `general`：保留 AstrBot 原生 MiniMax 通用聊天流程。

## 5. 架构

### 5.1 路由顺序

```text
QQ 群明确 @机器人
  -> 读取每群策略和全局 MentionCommandPolicy
  -> DeterministicMentionRouter
       -> 固定短语匹配成功
            -> EventAdapter
            -> 本地文本或图片
            -> 停止事件传播，零 MiniMax
       -> 未匹配
            -> llm_mode=disabled：本地能力提示，零 MiniMax
            -> llm_mode=anime_only/general：放行 AstrBot 原生 Agent
                 -> MiniMax
                 -> anime_readonly_query
                      -> Anime Core
                      -> Reply + 只读文本结果
                      -> 有本地图片：直发并停止 Agent
                      -> 无图片：MiniMax 组织文本
```

### 5.2 模块边界

`DeterministicMentionRouter` 只负责：

- 判断事件是否为群内明确 `@机器人`；
- 调用现有锚定解析器；
- 对“匹配 / 未匹配”作三态路由，不解释开放式自然语言；
- 把匹配后的 `Intent` 交给 `EventAdapter`。

`MentionCommandPolicyRepository` 负责：

- 读取全局单例匹配策略，缺失时返回内置默认值；
- 验证精确短语和参数前缀的长度、数量、重复与跨动作冲突；
- 用版本号执行并发安全更新，并支持恢复默认；
- 向解析器提供不可变的规范化策略对象。

`ReadonlyAnimeExecutor` 负责保留一次执行产生的两种视图：

- 对外模型视图：状态、动作、受限文本、候选数量和防猜测指令；
- 内部呈现视图：原始 `Reply`，只在当前事件内使用，不序列化图片路径给模型。

图片 `Reply` 增加只供 fallback 使用的确定性文本。图片工厂在同一次查询和组装中同时产出
本地 PNG 与 fallback 文本；固定命令只发送图片块，Readonly Tool 使用 fallback 文本生成
模型视图。关闭图片优先或图片发送失败时，不需要重新查询数据库或重新渲染。

`AnimeReadonlyTool` 负责选择发送策略：

- 没有图片时返回模型视图；
- 有安全本地图片时发送 MessageChain，成功后请求停止 Agent；
- 发送异常时记录有限日志并返回文本 fallback。

图片根目录验证继续集中在现有 `rendering` 模块，Tool 不自行复制路径校验规则。

## 6. 状态与并发

- 每次 Tool 调用只使用当前 `ContextWrapper` 中的事件，不跨事件保存 Reply；
- `LLMPolicyGuard` 继续按群号和消息号隔离进行中的轮次；
- Agent 停止标记只写入当前事件，不影响同群其他消息；
- 候选编号继续由现有 `InteractionSession` 按平台、群、用户和 TTL 隔离；
- 图片直发成功后即使 Agent 完成钩子被调用，也不得补发正文。

## 7. 配置与兼容

- `interaction_gateway_enabled=false` 继续保留，旧的全量有限短语入口不会重新抢占未知
  `@` 消息；
- 新的确定性 `@` 路由只处理全局策略中的严格固定短语，不依赖该旧总开关；
- 每群沿用 `mention_enabled`，在管理页标记为“确定性 @短语”；默认开启；
- 每群新增 `llm_mode`，只允许 `disabled`、`anime_only`、`general`；新群默认
  `anime_only`；
- 每群新增 `llm_image_reply_enabled`；默认开启，只控制自然语言 Tool 的图片直发，不改变
  固定命令的图片；
- 迁移把 `general_chat_enabled=true` 转为 `llm_mode=general`，其余现有群转为
  `llm_mode=anime_only`，随后移除旧布尔字段；
- 新增全局单例 `mention_command_policies`，保存 JSONB 别名映射、版本号和更新时间；
- 管理页新增“LLM 与 @入口”群设置，以及“全局固定短语”编辑区；所有写入继续要求机器
  人管理者身份、版本号和审计记录；
- 别名每项规范化后为 1 至 24 个字符；每个动作最多 12 个别名；配置总量最多 96 项；
- `/番剧` 命令行为不变；
- 有可逆数据库迁移，但无新增公网端口或密钥。

## 8. 错误处理

- 解析未匹配：静默放行给 AstrBot，不生成固定入口错误；
- LLM 模式关闭且解析未匹配：返回本地能力提示，不调用 Provider；
- 全局别名存在重复、跨动作冲突、空值或超限：拒绝整次保存，不部分更新；
- 本地查询失败：返回现有安全错误文本，不转为模型猜测；
- 图片渲染失败：使用同次查询的文本 fallback；
- 图片路径越界、文件缺失或非 PNG：拒绝直发并使用文本 fallback；
- QQ 图片发送失败：不停止 Agent，允许 MiniMax 基于真实文本结果回答；
- Agent 停止请求异常：发送成功的图片仍是唯一业务结果，完成钩子清空额外正文。

## 9. 测试与验收

### 9.1 单元测试

- 固定短语表逐项映射到正确 `IntentKind`；
- 自定义全局别名逐项映射到正确 `IntentKind`；
- 别名规范化、数量、长度和冲突校验覆盖边界值；
- 开放式相似语句返回未匹配；
- Reply 同时保留模型文本视图和内部图片视图；
- 安全 PNG 生成图片 MessageChain，越界或无效文件拒绝；
- 图片成功后设置当前事件停止信号；
- 图片失败后返回文本且不设置停止信号。

### 9.2 集成测试

- 已识别 `@` 短语直接得到文本或图片，并停止传播；
- 未识别 `@` 短语放行到 LLM 请求钩子；
- `llm_mode=disabled` 时未识别短语得到本地帮助且 Provider 未被调用；
- `llm_mode=anime_only` 与 `general` 分别保留现有番剧守卫和通用聊天行为；
- 每群关闭 `mention_enabled` 后固定短语不再本地执行；
- 每群关闭 `llm_image_reply_enabled` 后 Tool 保持文本回答；
- 全局别名更新立即对所有群生效，并写入管理审计；
- 今日、本周、唯一搜索、详情和下一集复用现有图片工厂；
- 多候选编号会话仍按群和用户隔离；
- 订阅、退订不经过 MiniMax；
- `llm_mode=anime_only` 时，未匹配的非番剧问题仍被策略守卫替换为帮助。

### 9.3 生产验收

在真实测试群验证：

1. `@机器人 今天播什么` 直接显示今日排期图；
2. `@机器人 搜番 <唯一标题>` 直接显示番剧卡片；
3. `@机器人 我的订阅` 直接返回确定性结果；
4. `@机器人 你觉得这部番怎么样` 进入 MiniMax；
5. LLM 模式为“仅番剧”时，`@机器人 今天天气怎么样` 返回番剧能力提示；
6. `/番剧 今天` 继续显示原图片；
7. 把测试群 LLM 模式切到“关闭”，第四项改为本地能力提示且没有 Provider 请求；
8. 新增一个全局今日别名后，所有启用确定性短语的群都能零 MiniMax 执行；
9. 观察 AstrBot 日志，前三项没有 MiniMax Provider 请求，第四项在对应模式下存在请求；
10. 图片 Tool 路径只发送一条图片，不出现重复模型正文。

自动化通过只证明代码和容器链路正确，真实 QQ 客户端显示与 Provider 请求数量仍属于生产验收。

## 10. 发布与回滚

按现有 ACR 流程发布，Worker 和 AstrBot 使用同一应用镜像，NapCat 保持不变。发布后检查
插件加载、OneBot 重连、容器健康、确定性短语日志和真实 QQ 图片。

迁移可逆。回滚时把 `llm_mode=general` 映射回 `general_chat_enabled=true`，其他模式映射为
`false`；删除新增每群图片字段和全局别名表。自定义别名在降级时会丢失，因此发布前的
数据库备份是完整恢复它们的唯一方式。
