# 番剧日期、精确放送与目录可观测性修复设计

- 日期：2026-07-30
- 状态：已确认，直接实施
- 适用版本：v0.4.x

## 1. 背景与生产证据

生产环境在北京时间凌晨执行“今日番剧”时返回前一天。线上数据库同时显示目录同步仍在
运行，但精确放送覆盖不足：119 部 Bangumi 番剧中只有 13 部建立 AniList 映射；当前
周四 13 条放送记录均只有日期。管理页没有已同步番剧目录，也没有持久化 Bangumi 来源
状态，因此无法从页面区分“目录已同步但缺少精确时刻”和“同步已停止”。

## 2. 目标

1. “今日”和“本周”严格按群配置时区计算，显式日期不发生 UTC 偏移。
2. 精确放送按 `air_at` 落入群时区日期；只有日期的 Bangumi 记录保持来源日期语义。
3. 同一 Anime、同一集的 AniList 精确记录优先于 Bangumi 日期记录，列表不重复。
4. 在不接受低置信度映射的前提下，提高 AniList 自动映射覆盖。
5. 持久化 Bangumi 最近成功、失败与错误状态。
6. 管理页增加已同步番剧目录、来源、下一次放送、精度、映射和最近同步信息。
7. 总览展示目录规模与精确时刻覆盖，支持判断同步完整度。

## 3. 方案比较

### 方案 A：只把 UTC `now` 转为北京时间

改动最小，但精确 `air_at` 仍然使用数据库中的 UTC `air_date` 归日，显式日期、其他群
时区以及跨午夜节目仍可能错误。不采用。

### 方案 B：以本地日历边界查询，日期记录与精确记录分流

调用方传入群时区和目标本地日期。日期-only 记录使用 `air_date`；精确记录使用本地
零点转换出的 UTC 半开区间筛选。展示时把精确记录重新投影为群本地日期，并在结果层按
Anime 与集数选择精确来源。采用此方案。

### 方案 C：迁移并重写所有历史 `air_date`

可以统一字段含义，但需要数据迁移且无法让一个存储日期同时满足多个群时区，风险高。
不采用。

## 4. 查询语义

- 隐式“今日”使用 `now.astimezone(group_timezone).date()`。
- 显式 `YYYY-MM-DD` 直接作为目标本地日期，不先转换成 UTC datetime。
- 精确记录查询范围为 `[本地零点转 UTC, 次日本地零点转 UTC)`。
- 日期-only 记录查询 `air_date == target_date`。
- 本周以群本地日期所在周一至下周一为边界，采用相同分流。
- 同一 `anime_id + episode_label` 同时命中时优先 `air_at` 非空记录。
- 精确记录返回给展示层的 `air_date` 使用群本地日期。

## 5. AniList 映射

继续要求非成人、完整首播日期一致且唯一候选。标题证据从“Bangumi 日文名只与 AniList
native 比较”扩展为：

- Bangumi `title_jp`、`title_cn`；
- AniList `native`、`romaji`/`english` 投影标题；
- 任意一组规范化后完全一致即可成为候选。

仍然只有唯一候选才自动确认；多个候选或无候选不落 confirmed，不使用模糊相似度。
管理页显示 AniList 是否已映射，便于后续人工处理剩余缺口。

生产发布验证发现，旧循环会先批量刷新最多 100 个已确认 AniList 条目，再做缺失映射，
两次请求一条的刷新足以在映射前耗尽公共 API 配额。修正后的预算顺序为：

- Bangumi 目录周期只刷新 Bangumi 已知条目；
- AniList 先处理最多 20 个缺失映射，再刷新最多 10 个已确认条目；
- 标题搜索已有唯一精确候选时不再请求第二个别名；
- 新确认链接直接补一次放送计划，不重复拉取同一媒体详情；
- 刷新遇到 rate limit 后立即停止该小批量，不继续消耗请求。

生产验证还发现 Worker 的周期海报预热会把全部历史 `SourceSnapshot` 取回 Python 后再
去重，在 192 MiB 容器限制下触发 memcg OOM。修正为数据库内按
`anime_id + provider` 选最新快照，并最多向 Worker 返回 `limit * 2` 行；不改变海报
来源优先级、缓存目录或其他服务内存配额。

## 6. 来源状态

一次目录周期中 Bangumi calendar discovery 与已知条目 ingest 都成功后，写入 Bangumi
`last_success_at` 并清除旧错误。任一步失败都写入 `last_failure_at` 和安全错误摘要。
管理任务触发的完整目录同步遵循同一状态语义。

## 7. 管理页

新增只读 `catalog` API 和“番剧目录”页签，支持标题搜索与分页。每行展示：

- 统一番剧标题与内部 ID；
- 已确认来源；
- 下一集日期、时间、集数和 `exact/date_only` 精度；
- AniList 映射状态；
- 最近来源快照或放送记录更新时间。

总览新增：

- 已同步番剧数；
- AniList 已映射数；
- 未来有放送计划数；
- 其中具有精确时刻的番剧数。

页面不提供编辑标题、放送时间或任意 SQL 能力。
