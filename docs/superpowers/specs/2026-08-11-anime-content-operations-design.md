# 番剧内容运营：周报、每日资源汇总与群投票设计

- 日期：2026-08-11
- 状态：已确认
- 范围：以 bot 持有者为唯一配置者，为现有 AstrBot + NapCat 群聊追番服务增加低频内容运营能力

## 1. 背景

项目已经具备今日本周查询、周历与日历图片、用户订阅、预计放送提醒、Mikan 实际资源
通知、群订阅热度、统一发送限频和持久化熔断。bot QQ 账号成为群管理员后，可以使用
`@全体成员` 和精华消息等能力，但管理员身份本身不能消除普通 QQ 小号通过 NapCat 接入
所面临的平台风控风险。

本设计把管理员权限限定为番剧内容的低频发布工具，不建设群管理机器人。内容运营由三类
能力组成：每周周报、每日实际资源汇总和可配置主题的群投票。现有针对订阅者的即时资源
通知继续保留。

## 2. 目标

- 每群每周最多发布一份番剧周报，并在发送成功后设为精华；
- 每群每天最多发送一份实际资源更新汇总，并按配置使用一次 `@全体成员`；
- 保留现有按番剧、集数和订阅筛选产生的即时资源通知；
- 支持“本周最佳”“下周最期待”“本季度最喜欢”和“群内共看”四种投票主题；
- 所有配置、预览和人工发布操作只允许 bot 持有者通过 AstrBot 管理后台执行；
- 复用现有限频、Outbox、熔断、审计、群时区和安全内容边界；
- 发送、置精、取消精华和投票在重启、重复调度及不确定投递结果下保持幂等或安全停止。

## 3. 非目标

- 不授予 QQ 群主、QQ 群管理员或普通成员任何机器人配置权限；
- 不增加群内配置命令，也不向 QQ 群角色映射 Dashboard 权限；
- 不自动禁言、踢人、审核入群、修改群名称、群公告、群名片或专属头衔；
- 不建设 QQ 原生群投票，不依赖表情回应充当可靠投票记录；
- 不让群成员提交任意投票文本、URL 或未通过内容过滤的候选；
- 不改变 Mikan 五分钟轮询、同集十分钟资源聚合、就近集数选择或资源详情查询；
- 不把周报、日报或投票发送到私聊；
- 不在本设计阶段修改代码、部署或打开任何生产群开关。

## 4. 权限模型

### 4.1 唯一配置者

bot 持有者是唯一内容运营配置者。配置入口沿用仅绑定本机并通过 SSH 隧道访问的 AstrBot
管理后台，复用 Dashboard 登录、TOTP、写开关和现有审计能力。第一阶段操作者仍统一记录
为 `owner`。

bot 持有者可以：

- 为每个群启用、关闭或调整周报与日报；
- 决定日报是否使用 `@全体成员`；
- 预览、确认或取消一次周报、日报或投票发布；
- 选择投票主题，审核自动候选或从内部番剧库选择候选；
- 暂停内容运营发送，查看失败、额度和审计状态。

### 4.2 QQ 群内角色

QQ 群主、QQ群管理员和普通成员都只能使用现有查询、管理自己的订阅和参与当前投票，
不能修改群时区、发送时间、`@全体成员`、候选、限频、静默时段或暂停状态。

bot QQ 账号的群管理员身份只提供执行 `@全体成员`、设置精华和取消精华所需的平台能力，
不作为任何授权依据。失去群管理员身份只会让相应动作安全失败，不会把权限转交给群主或
其他管理员。

## 5. 功能设计

### 5.1 每周番剧周报

周报复用当前本周查询、群时区、周历图片渲染和群订阅热度，不在发送时访问 Bangumi、
AniList、Mikan 或远程海报。

每群可配置一个本地星期和发送时间。功能默认关闭，bot 持有者先在后台预览，确认显示、
时区和候选内容后再开启计划。周报沿用当前周日到周六的七日范围，以本地周日日期作为周期
标识。每个群、每个周期只有一个周报业务键；重复调度、Worker 重启或重复确认不会再次
发送。

周报规则：

- 发送一张现有周历样式图片，失败时使用等价结构化文本；
- 不使用 `@全体成员`，避免与每日资源汇总叠加提醒；
- 新周报发送成功并取得平台消息 ID 后，调用 OneBot `set_essence_msg` 设为精华；
- 只有新精华设置成功后，才取消上一份由本系统设置的周报精华；
- 取消旧精华失败时保留新周报，不撤回任何消息，并记录安全错误；
- 不自动撤回历史周报；只有重复或误发的本机器人消息允许 bot 持有者人工撤回；
- 发送成功但无法取得消息 ID 时，将周报记录为已发布、置精记录为失败，不重复发送周报。

周报可以附带上一个已结束投票的主题、胜出番剧和票数，不展示参与者 QQ 号或名单。

### 5.2 每日实际资源汇总

日报按 Mikan 已持久化的 `ResourceRelease` 判断“实际更新”，不把预计放送时间当成资源
发布。收录范围限定为本群至少有一名有效订阅者的番剧；同一番剧、同一集即使有多个字幕组
或跨多个十分钟批次，也只在日报中占一行。

日报与现有即时资源通知并存：

| 类型 | 时效 | 群内受众 | 内容 |
|---|---|---|---|
| 即时资源通知 | 同集资源聚合约十分钟后 | `@` 筛选条件匹配的订阅者 | 番剧、集数和有限资源规格摘要 |
| 每日资源汇总 | 每晚一个动态窗口 | 按配置 `@全体成员` 一次 | 番剧、集数和首次资源时间 |

现有即时资源通知的业务键、订阅筛选、就近集数、无主动 Mikan 外链和资源详情命令均保持
不变。日报不列字幕组、语言、分辨率或 URL，避免把即时通知完整重复一遍。

#### 5.2.1 发送时间算法

日报采用“固定锚点 + 安静窗口 + 最晚截断”：

- 默认本地锚点为 `22:30`；
- 默认安静窗口为 20 分钟；
- 默认最晚截断为 `23:30`；
- 到达锚点时，如果最近 20 分钟没有新资源，立即发送；
- 如果仍有资源到达，发送时刻延后到最后一条符合条件的资源出现 20 分钟后；
- 无论资源是否继续出现，最晚在 `23:30` 截断；
- 截断后的资源进入下一群本地日报周期，不触发当天第二次日报；
- 当期没有符合条件的资源时不创建发送任务。

日报周期以群本地 `23:30` 为边界，例如某日周期为前一日 `23:30` 之后至当日 `23:30`
为止。周期键固定为群 ID 加本地周期日期。一次日报明确失败、结果不确定、超过过期时间或
被熔断时均不跨周期补发，避免第二天形成历史突发。

bot 持有者可以在安全范围内调整锚点、安静窗口和最晚截断，但锚点必须早于截断、安静
窗口必须能在截断前结束，且后台必须提示与群静默时段冲突的配置。

#### 5.2.2 `@全体成员` 保护

- 日报和 `@全体成员` 分别有独立开关，均默认关闭；
- 日报开启但 `@全体成员` 关闭时发送普通日报，不查询全体额度；
- 发送前通过 OneBot `get_group_at_all_remain` 读取当前群剩余次数；
- 额度为零、查询失败、bot 不再是群管理员或返回值无法确认时不发送该期日报；
- 每期消息最多包含一个 `qq="all"` 的 `at` 消息段；
- 不把平台返回的剩余额度解释为账号绝对安全；
- 明确拒绝、限频、账号验证、强制下线或不确定发送结果不自动重试；
- bot 持有者可以从管理后台立即关闭单群日报或全局主动发送。

### 5.3 群投票

投票由项目自身持久化，不依赖 QQ 原生投票或消息表情计数。每群同时最多有一个进行中的
投票，每个投票实例只有一个主题。

首版主题：

| 主题 | 自动候选范围 |
|---|---|
| 本周最佳 | 本周实际有放送记录或资源更新的合规番剧 |
| 下周最期待 | 下周有确定放送记录的合规番剧 |
| 本季度最喜欢 | 当前季度已收录的合规番剧 |
| 群内共看 | bot 持有者从内部番剧库手工选择 |

自动候选为 3 至 6 部。bot 持有者可以在发布前删除候选或调整顺序；手工候选只能引用内部
Anime ID，必须通过现有成人内容过滤，不接受任意文本和 URL。候选不足 3 部时不允许发布。

群成员使用固定命令：

- `/番剧 投票`：查看当前投票、候选编号和截止时间；
- `/番剧 投票 <编号>`：投票或把自己的票改为另一个候选；
- `/番剧 取消投票`：取消自己的票，不影响他人。

投票以平台、群、外部用户和投票 ID 隔离。每人一票，重复选择同一候选返回当前状态；改票
使用原子更新。群内只展示总票数，不展示 QQ 号、昵称、投票者列表或逐票动态。

投票开始消息不使用 `@全体成员`。截止后最多发送一条结果消息，也不使用
`@全体成员`；胜出结果同时可进入下一份周报。相同票数时明确显示并列，不用随机规则选择
单一胜者。

首版由 bot 持有者每周手工选择主题、审核候选并确认发布，不做自动主题轮换。自动轮换属于
后续独立范围。

## 6. 模块边界与数据流

新增 `content_operations` 领域模块，负责内容策略、日报周期、周报发布记录和投票状态。
它不负责 Mikan 拉取、番剧身份映射、QQ 连接或底层发送重试。

```text
Resource Worker
  ├─ 现有 Mikan Pipeline ──> ResourceRelease / 即时 release Job
  ├─ Daily Digest Planner ──> daily_release_digest Job
  └─ Weekly Report Planner ─> weekly_report Job

AstrBot Plugin
  ├─ 现有命令与即时通知
  ├─ Poll Command Adapter ──> PollService
  └─ Content Publisher ─────> SendGovernor / Outbox
                               └─ GroupContentGateway
                                  ├─ 发送消息与 @全体
                                  ├─ 查询 @全体剩余次数
                                  └─ 设置或取消精华

PostgreSQL
  ├─ group_runtime_settings
  ├─ content_publications
  ├─ content_polls / content_poll_candidates / content_poll_votes
  └─ notification_jobs / delivery_attempts / admin_audit_events
```

### 6.1 内容设置

扩展现有 `GroupRuntimeSetting` 和 `GroupRuntimePolicy`，不新增通用键值配置表。增加周报启停
与本地计划、日报启停、`@全体成员` 开关、锚点、安静窗口和最晚截断字段。写入继续使用
现有乐观版本号，管理后台并发修改时返回版本冲突，不覆盖较新的配置。

`active_notifications_enabled`、群暂停、全局或群级 `DeliveryControl` 仍是更高层总闸；任何
总闸关闭时，周报、日报、投票发布和现有即时通知都不得发送。投票参与命令属于被动交互，
只受群被动入口与普通命令限频控制。

### 6.2 发布记录

新增 `content_publications` 保存：群、发布类型、周期业务键、Notification Job、平台消息
ID、精华状态、发布状态和时间。对 `(chat_group_id, publication_type, period_key)` 建立唯一
约束，用于阻止重复周报、日报、投票开始或投票结果。

平台消息 ID 只用于本系统发送消息的后续置精、取消精华和人工纠错，不允许对群成员消息
执行这些动作。

### 6.3 投票记录

- `content_polls`：群、主题、状态、开始与截止时间、创建者和周期键；
- `content_poll_candidates`：投票、Anime ID、稳定编号和显示顺序；
- `content_poll_votes`：投票、外部用户 ID、候选和更新时间；
- 对 `(poll_id, external_user_id)` 建立唯一约束；
- 结束的投票不可继续写票，取消投票只删除或失活当前用户的一票；
- 投票保留周期沿用运营数据策略，后台默认只显示聚合结果。

### 6.4 平台网关

`GroupContentGateway` 隔离 AstrBot/NapCat 细节，提供发送、查询全体额度、设置精华、取消
精华和撤回本机器人消息的明确操作。实现通过当前 Compose 内部 OneBot 连接调用，不增加
NapCat 公网端口，不暴露 Token，也不绕过 SendGovernor 或 Outbox。

内容发布需要返回平台消息 ID。若当前 AstrBot 高层发送接口无法稳定返回消息 ID，平台
适配层通过同一内部 OneBot adapter 的动作入口发送并取得 ID；业务层不直接访问 NapCat
HTTP 地址。

## 7. 调度、优先级与幂等

所有主动内容都进入现有 Notification Outbox。新增 `weekly_report`、
`daily_release_digest`、`poll_open` 和 `poll_result` 类型，并为每个类型定义稳定业务键和
过期时间。

发送优先级从高到低为：

1. 用户正在等待的查询回复；
2. 临近开播提醒；
3. 现有即时资源通知；
4. 每日资源汇总；
5. 周报、投票开始和投票结果；
6. 管理员测试消息。

日报、周报和投票发布全部属于主动消息，必须计入现有全局、群级和主动发送额度，不能借
`ADMIN` 类型绕过限频。投票命令回复仍按互动消息限频。

稳定业务键示例：

- `content/weekly/<group-local-sunday-date>`；
- `content/daily-release/<group-local-period-date>`；
- `content/poll-open/<poll-id>`；
- `content/poll-result/<poll-id>`。

不确定投递结果统一记录为 `unknown`，不自动重试。周报发送与置精是两个可审计步骤；只有
发送成功才尝试置精，置精失败绝不再次发送周报。

## 8. 管理后台

在现有 Anime 插件内嵌管理页增加“内容运营”区域，不新增登录系统或公网服务。

页面包括：

- 每群周报、日报、`@全体成员` 和时间窗口设置；
- 下一次计划时间、上一周期结果、消息 ID 是否可用和精华状态；
- `@全体成员` 剩余额度的只读状态与最近失败摘要；
- 周报与日报预览；
- 投票主题、自动候选、候选审核、开始与提前结束；
- 全局和单群暂停入口；
- 最近发布、投票和管理员动作审计。

所有写操作使用明确确认。页面只显示必要群标识和聚合票数，不显示订阅者或投票者 QQ 号。
后端再次执行所有授权、版本、候选和安全校验，不能信任前端隐藏按钮。

## 9. 错误处理与降级

| 情况 | 行为 |
|---|---|
| 周报图片渲染失败 | 同一任务发送等价结构化文本 |
| 周报发送成功但置精失败 | 保留周报和旧精华，记录失败，不重发 |
| 取消旧精华失败 | 保留新旧精华状态并提示 bot 持有者人工处理 |
| `@全体成员` 额度为零或无法确认 | 跳过当期日报，不改为普通消息，不重试 |
| bot 失去管理员身份 | 周报可发送但置精失败；要求 `@全体成员` 的日报跳过 |
| 日报窗口内没有符合条件的资源 | 不创建发送任务 |
| 日报发送结果不确定 | 记录 `unknown`，本周期不再发送 |
| 投票候选不足或包含不合规番剧 | 拒绝发布并在后台说明原因 |
| 同一用户并发改票 | 唯一约束和原子更新保留最后一次成功选择 |
| 数据源或 Worker 延迟 | 不猜测更新；超过周期与过期时间后不补发历史日报 |
| 群暂停、退群、禁言或熔断 | 保持任务可审计并按现有策略失败、过期或暂停 |

## 10. 风控与内容安全

- 所有新功能默认关闭，只在 bot 持有者明确配置后启用；
- 首次发布在测试群 canary，不直接在全部生产群打开；
- 每群每日本设计最多增加一条带 `@全体成员` 的消息；
- 周报、投票开始和结果均不使用 `@全体成员`；
- 日报为空不发送，失败和不确定结果不自动补发；
- 主动消息不包含任意用户文本、磁力链接、短链接或未校验 URL；
- 候选继续使用 `nsfw=false` 和现有来源映射边界；
- 不通过随机时间、随机文案、模拟人工行为或拆分消息规避平台检测；
- OneBot 管理动作使用独立安全日志，不记录 Token、完整平台响应、QQ 号名单或消息正文；
- 平台额度、HTTP 成功、容器健康和真实 QQ 客户端可见性分别验收，不互相替代。

## 11. 验收与测试

### 11.1 单元测试

- 群时区、跨日、跨周、夏令时、锚点、安静窗口和 `23:30` 截断；
- 截断后资源进入下一周期，同一番剧同集在日报中只出现一次；
- 日报只选择本群至少一名有效订阅者关注的番剧；
- 空日报、额度不足、管理员身份缺失和 unknown 均不重试；
- 四种投票主题的候选范围、3 至 6 部限制、成人内容过滤和并列结果；

## 12. 发布顺序与回滚

1. 增加数据模型和只读后台状态，所有新开关默认关闭；
2. 增加投票的被动命令与持久化，不发送自动投票消息；
3. 增加周报 Outbox 与置精网关，在测试群人工发布；
4. 增加日报规划、额度检查和预览，先以不发送模式验证一个完整周期；
5. 在测试群显式开启一次日报和 `@全体成员`，完成真实客户端验收；
