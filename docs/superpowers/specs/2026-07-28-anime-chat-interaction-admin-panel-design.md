# Anime QQBot 群聊交互、发送保护与内嵌管理面板设计

日期：2026-07-28  
状态：已确认，等待实施计划

## 1. 背景

v0.2.0 已经通过 NapCat、OneBot 11 和 AstrBot 在普通 QQ 小号上运行，并完成 Bangumi
目录查询、订阅、开播提醒、Mikan 聚合通知及持久化 Outbox。真实群验证表明，底层能力
已经可用，但产品交互仍存在三个主要问题：

1. 普通用户必须记忆 `/番剧 <子命令>`，搜索候选和高级订阅设置还会暴露内部 UUID；
2. 直接监听“今天”“搜索”“订阅”等自然语言容易误识别正常群聊；
3. AstrBot 和 NapCat WebUI 只能管理框架及 QQ 连接，没有番剧业务控制面板；
4. 被动回复和主动通知没有共享的发送限频器，通知积压时可能形成突发消息。

本设计在不恢复 QQ 官方机器人、不引入大模型依赖、不新增运行容器的前提下，改善群聊
入口、发送安全和所有者运维能力。

## 2. 目标

- 同时支持 `/番剧`、`@机器人` 和免 `@` 专用短命令；
- 默认避免普通聊天误触发，免 `@` 入口由机器人所有者显式开启；
- 使用短期候选会话和数字选择隐藏内部 UUID；
- 所有被动回复与主动通知经过统一发送限频和熔断；
- 在 AstrBot WebUI 内提供仅机器人所有者可用的番剧业务管理页；
- 允许所有者管理群设置、订阅、来源映射、通知、限频和同步任务；
- 所有高风险状态变更可审计、可恢复、可关闭；
- 保持现有 ACR 单镜像部署和 2 GiB 服务器运行边界。

## 3. 非目标

- 不建设独立登录系统或向 QQ 群主、群管理员授予机器人配置权限；
- 不通过 Nginx 将 AstrBot WebUI 暴露到公网；
- 不建设可编辑标题、简介、评分和放送时间的内容 CMS；
- 不提供 SQL、Shell、任意 HTTP 请求或任意上游 URL 输入；
- 不监听无明确唤醒方式的开放式自然语言；
- 不通过模拟人工行为、随机文案等方式规避 QQ 风控；
- 不保证普通 QQ 小号不存在登录、社交或发送限制风险；
- 不新增 Redis、独立前端容器或独立管理服务。

## 4. 总体架构

在现有 Anime AstrBot 插件内增加三个边界清晰的模块：

```text
QQ 群消息
   │
   ▼
InteractionGateway
   │
   ▼
Anime Core / PostgreSQL
   │
   ▼
SendGovernor
   │
   ▼
AstrBot → NapCat → QQ

AstrBot WebUI
   │
   ▼
AdminPage → Admin API → 管理用例 → PostgreSQL
                                  │
                                  └─ operator_jobs → Worker
```

### 4.1 InteractionGateway

统一完成消息标准化、唤醒判定、固定意图解析、权限判定和短期候选会话解析。它只输出
平台无关的 Intent，不直接查询数据库或发送 QQ 消息。

### 4.2 SendGovernor

为命令回复、开播提醒、Mikan 提醒和管理员测试消息提供统一的发送许可、优先级、冷却、
熔断和指标。任何调用 AstrBot 发送接口的路径都必须先经过该模块。

### 4.3 AdminPage

使用 AstrBot `v4.26.7` 已支持的 Plugin Pages 和插件 Web API，复用 AstrBot Dashboard
登录与 TOTP。页面通过明确的管理 API 调用应用服务，不直接操作 ORM 或执行 SQL。

Anime Core、Worker 和持久化模型继续保持与 AstrBot UI 解耦。

## 5. 群聊触发模型

### 5.1 每群触发策略

每个群保存独立的 Trigger Policy：

| 入口 | 新群默认值 | 说明 |
|---|---:|---|
| `/番剧` | 开启 | 已启用群的稳定兼容入口，不被触发模式单独关闭 |
| `@机器人` | 开启 | 默认的简短交互入口 |
| 免 `@` 专用短命令 | 关闭 | 机器人所有者显式开启 |
| 开放式自然语言监听 | 不支持 | 不扫描普通群聊内容 |

机器人所有者仍可通过现有 `chat_groups.enabled` 停用整个群；停用后所有被动入口和主动
提醒均停止。`/番剧` 无参数时返回精简菜单，不再返回解析错误。完整命令帮助保留在
“帮助”入口。

### 5.2 免 `@` 专用短命令

第一版支持以下明确格式：

```text
今日番剧
本周番剧
搜番 <关键词>
追番 <关键词或候选编号>
退订 <关键词或候选编号>
我的追番
```

匹配必须从消息开头开始并消费完整命令结构，不做子串扫描。普通消息例如“今天聊一部
番剧”“我想搜索一下”不会触发机器人。

### 5.3 `@机器人` 入口

移除消息开头对机器人的一次明确 `@` 后，再执行受控的确定性解析。允许比免 `@` 入口
稍自然的固定表达，例如：

```text
@机器人 今天
@机器人 本周有什么
@机器人 搜一下芙莉莲
@机器人 追这个
```

解析器使用显式规则和同义词表，不默认调用大模型。无法唯一判断意图时返回精简帮助，
不猜测并执行状态修改。

### 5.4 候选会话

搜索产生多个结果时建立短期 Interaction Session：

- 以平台、群、用户为隔离键；
- 保存候选 Anime ID、有序短编号、机器人结果消息 ID 和过期时间；
- 默认有效期 5 分钟；
- 同一用户的新搜索覆盖旧会话；
- `看 1`、`追番 1`、`退订 1` 可继续操作；
- 单独的 `1` 只有在引用或回复对应机器人结果消息时才生效；
- 其他用户、其他群或过期会话不能复用候选；
- 会话存入 PostgreSQL 并由 Worker 定期清理，不依赖 AstrBot 进程内状态。

状态修改仍返回修改后的明确结果。无法确认目标时不创建或取消订阅。

### 5.5 群内权限

群设置只允许配置的机器人所有者修改，以 AstrBot `event.role == "admin"` 作为群内
管理入口的授权结果。QQ 群主或群管理员身份不授予机器人配置权限。普通群成员只可以
查询番剧以及管理自己的订阅，不能修改群触发方式、主动提醒、静默时段、限频或暂停
状态。

## 6. 统一发送限频与熔断

### 6.1 默认限频

以下值是面向少量群的保守产品默认值，不是 QQ 官方安全阈值：

| 维度 | 默认值 |
|---|---|
| 全局发送 | 每 2.5 秒 1 条，突发容量 2 |
| 同一群普通发送 | 至少间隔 5 秒 |
| 同一用户命令 | 冷却 5 秒，每分钟最多 10 次 |
| 同一群主动提醒 | 至少间隔 60 秒，10 分钟最多 3 条 |

参数可以在所有者面板修改，但必须有安全范围校验；明显激进的值显示风险警告。

### 6.2 优先级

发送顺序为：

1. 正在等待的用户查询回复；
2. 临近开播提醒；
3. Mikan 聚合提醒；
4. 管理员测试和非紧急后台消息。

调度必须避免低优先级永久饥饿。查询回复等待超过交互上限时返回简短限频提示，而不是
无限挂起。

### 6.3 主动通知领取

Outbox Dispatcher 不再每轮领取 10 条后连续发送。它先向 SendGovernor 申请发送容量，
再按容量逐条领取任务。没有容量时任务保持 pending，不提前占用长租约。

现有开播 2 小时、Mikan 24 小时过期语义保持不变。过期任务不在服务恢复后补发。

### 6.4 结果分类与熔断

- 明确未发送的临时网络错误：有限次数退避重试；
- QQ 已拒绝的永久错误：标记 failed，不自动重试；
- 发送结果不确定：标记 unknown，不自动重试；
- QQ 限频、账号验证、强制下线或连续发送失败：触发全局主动通知熔断；
- 熔断期间继续生成持久化任务，但不投递；
- 熔断状态跨进程重启保留，只能由所有者在面板确认后恢复；
- 单群禁言、退群或持续失败可以触发群级暂停，不必停止其他群。

## 7. AstrBot 内嵌管理面板

### 7.1 访问与权限

- 页面入口位于 Anime 插件详情；
- AstrBot WebUI 继续绑定 `127.0.0.1:6185`；
- 第一阶段只通过 SSH 隧道访问；
- 复用 AstrBot Dashboard 登录与 TOTP；
- 第一版只有机器人所有者，审计操作者统一记为 `owner`；
- QQ 群主和群管理员不获得 Web 面板账号，也不因 QQ 群角色获得群内配置权限。

### 7.2 页面范围

#### 总览

- OneBot、AstrBot 插件、Worker 和 PostgreSQL 状态；
- Bangumi、AniList、Mikan 最近同步、失败和下一次执行时间；
- 群、订阅、待处理映射和通知任务数量；
- 全局主动通知、熔断和积压状态。

#### 群管理

- 群号、名称、最近活跃和 UMO 状态；
- 三类触发入口状态；
- 主动提醒开关、时区、静默时段；
- 群级限频、暂停原因和最近投递；
- 暂停或恢复单个群。

#### 订阅管理

- 按群、用户或番剧查询；
- 查看语言、字幕组和分辨率筛选；
- 取消异常订阅；
- 第一版不替用户批量创建订阅。

#### 来源映射

- 查看 unresolved、probable、confirmed 和 rejected；
- 展示来源 ID、标题、匹配方法和证据；
- 确认或拒绝 AniList 映射；
- 通过 AniList/Mikan 数字 ID 建立人工映射；
- 不接受任意来源 URL。

#### 通知与限频

- 查询 pending、leased、sent、retry、unknown、failed 和 expired；
- 取消未发送任务；
- 对明确失败任务执行单条重试；
- unknown 经过二次警告后才允许人工补发；
- 查看全局和群级发送额度、积压及熔断；
- 暂停或恢复主动通知。

#### 数据源与任务

- 查看同步状态、下一次执行时间和最近错误；
- 提交立即同步 Bangumi、AniList 或 Mikan 的操作；
- 查看后台管理任务进度和结果。

### 7.3 面板错误状态

所有页面必须覆盖加载中、空数据、失败、无权限和分页状态。写操作使用明确确认反馈；
失败时保留当前页面状态并展示安全错误摘要，不展示堆栈、连接串或上游响应正文。

## 8. 持久化模型

采用一次增量迁移增加以下模型。

### 8.1 `group_runtime_settings`

以 `chat_group_id` 唯一关联现有 `chat_groups`，保存 mention、direct shortcut、主动提醒、
静默时段、限频覆盖、暂停状态及更新时间。现有 `chat_groups.timezone` 和 `enabled`
继续作为群身份与总启停字段，不重复存储。

### 8.2 `interaction_sessions`

保存平台、群、用户、候选 ID 列表、结果消息 ID、创建时间和过期时间。对隔离键和
过期时间建立索引；同一隔离键最多保留一个当前会话。

### 8.3 `delivery_controls`

用明确的 scope kind 和 scope ID 表示全局或群级投递控制，保存暂停、熔断、原因、最近
异常和人工恢复时间。短期 Token Bucket 留在单 AstrBot 进程内，持久化暂停状态不能因
重启自动解除。

### 8.4 `operator_jobs`

保存受控后台任务：

```text
pending → running → succeeded
                  → failed
                  → cancelled
```

每个任务包含类型、受限参数、业务幂等键、租约、结果摘要和时间。Worker 领取来源同步
任务；AstrBot 消费者领取需要平台发送能力的管理任务。

### 8.5 `admin_audit_events`

保存操作者、操作类型、目标、修改前后安全摘要、时间、结果和失败原因。禁止保存密码、
Token、数据库连接串、完整上游载荷或完整异常堆栈。

## 9. 管理 API 与事务

管理页面只调用窄接口，例如：

```text
PATCH /groups/{id}/settings
POST  /mappings/{id}/confirm
POST  /mappings/{id}/reject
POST  /notifications/{id}/cancel
POST  /notifications/{id}/retry
POST  /sources/{provider}/sync
POST  /delivery/pause
POST  /delivery/resume
```

所有写接口要求：

- 输入类型、枚举和长度验证；
- 通过应用服务执行，不直接暴露 ORM；
- 数据修改与审计事件处于同一事务；
- 使用幂等键或当前版本检查防止双击重复执行；
- 高风险操作要求页面二次确认；
- 返回有限、安全、稳定的 DTO；
- 不接受 SQL、文件路径、Shell、任意 URL 或任意 Python 参数。

来源同步不在 Web 请求中执行。API 创建 operator job 后立即返回，页面轮询任务状态，
Worker 负责真正执行，页面关闭不会中断任务。

## 10. 可观测性

面板和结构化日志至少提供：

- 各入口匹配、拒绝和解析失败次数；
- 用户、群、全局限频命中次数；
- 各优先级排队数量和最长等待；
- sent、failed、unknown、expired 数量；
- 熔断、群暂停和人工恢复事件；
- operator job 等待与执行耗时；
- 数据源最近成功、失败、限频和下一次执行；
- Interaction Session 创建、使用、过期和隔离拒绝计数。

日志不记录完整群消息正文；诊断所需关键词应截断或散列。

## 11. 测试

### 11.1 单元测试

- 三类入口的成功样例和误触发反例；
- 群触发策略和权限；
- 候选会话过期、用户隔离和群隔离；
- 限频、优先级、公平性、熔断和恢复；
- 结果分类及 unknown 不自动重试；
- 审计敏感字段清理。

### 11.2 数据库与集成测试

- 空库升级、当前 head 升级、降级后再升级；
- 管理任务领取、租约恢复、取消和幂等；
- 面板与群命令修改同一群设置时结果一致；
- 重复映射确认和重复通知重试不产生重复数据；
- 重启后熔断保持、候选会话仍正确；
- Worker 与 AstrBot 并发访问任务和通知队列。

### 11.3 插件页与浏览器测试

- AstrBot `v4.26.7` 发现并加载 Plugin Page；
- 未经 Dashboard 登录不能调用管理 API；
- 页面加载、空数据、失败、分页和确认操作；
- 总览、群、订阅、映射、通知及来源工作流；
- 页面与 API 不泄露秘密。

### 11.4 真实群验收

- 普通消息“今天聊一部番剧”不触发；
- `@机器人 今天` 正常回复；
- 新群的“今日番剧”默认不触发；
- 机器人所有者开启后“今日番剧”正常回复；
- 用户甲的候选不能被用户乙使用；
- 通知积压恢复后按限频发送；
- 风控异常触发熔断且重启后不自行恢复；
- 面板操作产生审计记录；
- 现有 `/番剧` 命令保持兼容。

## 12. 分阶段上线

1. 增加持久化模型、应用服务和只读面板，保持现有命令与发送路径；
2. 在测试群启用 `@机器人` 路由并验证误触发反例；
3. 接入 SendGovernor，模拟命令突发和通知积压；
4. 由机器人所有者显式开启免 `@` 专用短命令；
5. 启用搜索候选会话、编号订阅、静默时段和群设置；
6. 开放面板写操作、人工映射和受控同步任务；
7. 完成真实群连续观察后再扩大群范围。

所有新入口和面板写操作都有功能开关。部署继续使用现有 ACR 单镜像流程，不新增容器。
迁移只增加新表和索引；回滚旧镜像时新表保留但不会被旧版本读取。

## 13. 已确认决策

- 三类群聊入口全部支持；
- 新群的免 `@` 短命令默认关闭；
- 管理面板使用 AstrBot Plugin Page；
- Web 面板第一版只供机器人所有者使用；
- QQ 群主和群管理员不获得机器人配置权限；
- 第一版是运维控制台，不是内容 CMS；
- AstrBot WebUI 暂时只通过 SSH 隧道访问；
- 采用 InteractionGateway、SendGovernor、AdminPage 三模块方案；
- 面板同步操作通过持久化 operator job 交给 Worker；
- 内部 UUID 不再作为普通用户的主要交互标识；
- 旧 `/番剧` 命令保留并继续作为兼容入口。
