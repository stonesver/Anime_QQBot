# 群订阅与番剧热度图片标识设计

## 目标

在不暴露群成员身份或个人订阅偏好的前提下，为番剧图片增加两类展示信息：

- 单番图片向当前命令发送者展示其在当前群的订阅状态。
- 周表和今日排期图片向当前群展示匿名的群内追番热度。

本设计不改变订阅、提醒或番剧数据的业务语义。

## 展示规则

### 单番图片

适用于搜索、详情、下次等只展示一部番剧的图片回复。

- 当且仅当当前发送者在当前群订阅该番剧时，显示金色“追番中”印章。
- 不显示订阅人数，也不显示其他成员信息。
- 私聊或缺少群上下文时，不显示该印章。

### 周表与今日排期

适用于 `/番剧 本周` 和 `/番剧 今天` 的图片回复。

- 对每部出现在排期中的番剧，按当前群的不同订阅用户数计算热度。
- 人数达到 3 时，显示 A1 粉色微光徽记：`✦ N 人追`。
- 人数低于 3 时不显示；不展示任何用户名、头像或个人订阅状态。
- 周表和今日卡片使用同一阈值与同一徽记语义，排期布局各自适配，不能遮挡标题、时间或集数。

## 架构

新增独立的订阅展示读取层，负责把订阅领域数据投影为只含展示所需信息的只读值：

- `viewer_follows`：给定群、发送者和单个番剧的布尔值。
- `group_follow_count_by_anime_id`：给定群和一批番剧 ID 的去重订阅人数映射。

该层以批量查询实现周表和今日排期的统计，避免逐条查询。统计范围严格为当前 `chat_group_id`；每个番剧以 `external_user_id` 去重，订阅的提醒开关不影响“正在追”的计数。

卡片回复工厂在已有番剧投影之后获取当前发送者的展示状态，并将其作为渲染覆盖信息传入图片渲染器。排期回复工厂批量获取群热度，并为每行排期创建带热度的展示行，再传入排期渲染器。

核心领域查询和订阅写入接口不依赖 AstrBot 上下文；只有回复组装层从消息上下文提供群和用户标识。

## 缓存与隔离

订阅状态会影响图片内容，缓存必须隔离：

- 单番卡片缓存键包含当前群、当前用户和 `viewer_follows` 的稳定作用域，以及渲染布局版本。
- 周表和今日排期缓存键包含当前群、日期/周范围、每部番剧的热度映射、阈值和布局版本。
- 不能复用另一群或另一用户产生的带订阅标识图片。

不把原始用户标识写入公开文件名或回复内容；缓存键使用既有哈希方式生成稳定的私有作用域。

## 降级与错误处理

订阅展示读取失败不得阻断原有番剧查询或图片回复：

- 记录带群和命令范围的告警日志，不记录用户可识别信息。
- 单番卡回退为不带“追番中”印章的原图片。
- 周表和今日卡片回退为不带热度徽记的原图片。
- 原有图片渲染失败时，继续保留文字回复兜底。

## 验证

新增或扩展测试覆盖：

- 群范围隔离：另一群的订阅不计入当前群。
- 人数去重：同一用户的重复行不重复计数。
- 阈值：2 人无徽记，3 人及以上显示徽记。
- 当前用户状态：只在同群且本人已订阅时显示“追番中”。
- 缓存隔离：不同群热度、不同当前用户订阅状态不能复用同一图片缓存。
- 展示读取失败时，卡片和排期仍产生无标识图片；原有文字兜底保持可用。

本地验证执行静态检查、现有测试套件及新增测试。部署后检查容器健康、插件加载与 OneBot 连接；真实 QQ 群内的图片呈现仍需发送命令做客户端验收。
