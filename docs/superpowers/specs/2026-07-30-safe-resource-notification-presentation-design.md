# 资源通知精简与受控链接设计

- 日期：2026-07-30
- 状态：待用户确认修订
- 范围：群内主动资源通知与用户主动查询资源详情

## 1. 背景与目标

当前资源通知直接拼接 Mikan 原始标题、重复解析规格、冗长的 UTC ISO 时间和每条资源 URL。消息
过长、难以扫读，并在主动推送中产生多个外链。

本次调整的目标是：

- 让用户在一屏内看清番剧、集数、资源数量和主要规格；
- 在每条资源摘要中保留易读的北京时间发布时间；
- Mikan 主动通知默认不发送 URL；
- 用户明确查询资源详情时，最多返回一个正常 Mikan 页面链接；
- 为未来接入 B 站 UP 主视频保留一个受控的可选动作链接槽位；
- 保持现有 `@`、聚合、订阅筛选、Outbox、限流和投递控制语义不变。

本设计不承诺任何域名在 QQ 中零风险。B 站规范视频链接仍可能被平台扫描、折叠或
拦截；系统只通过减少主动外链和限制来源降低暴露，不使用变形链接规避检测。

## 2. 主动通知格式

资源通知使用以下结构：

```text
@用户 📦 BanG Dream! YUME∞MITA · 第 6 集
发现 4 个资源
• ANi · 繁中 · 1080p · 07-24 06:00
• Prejudice-Studio · 简中 · 1080p · 07-24 07:36
• LoliHouse · 简繁 · 1080p · 07-24 08:12
另有 1 个资源

发送「资源详情 YUME 6」查看来源
```

规则：

- 标题行只出现一次番剧名和集数；
- 规格行最多展示 3 条，格式为“字幕组 · 语言 · 分辨率 · 发布时间”；
- 同一规格行内去重，不展示平台、编码、封装等低价值标签；
- 每条资源分别展示其发布时间，统一转换为 `Asia/Shanghai`，格式为 `MM-DD HH:mm`；
- 不展示原始发布标题、UTC ISO 时间、时区后缀、内部 UUID 或 Mikan URL；
- 超过 3 条时只显示剩余数量；
- 查询提示使用稳定、可输入的标题关键词，不暴露内部 UUID；
- 多位订阅者仍通过 AstrBot `At` 组件合并到同一条群消息。

## 3. 用户主动查询资源详情

增加固定命令：

```text
资源详情 <番剧关键词> [集数]
/番剧 资源详情 <番剧关键词> [集数]
```

查询只读取已持久化的 Resource Release，不实时请求 Mikan。标题匹配不唯一时返回
编号候选供用户选择；结果展示最新一条匹配资源的简短规格和一个正常 Mikan 页面
链接。一次查询最多发送一个 URL，并继续经过现有交互限流。

未找到番剧、集数或安全页面链接时返回纯文本说明，不拼接猜测 URL。该命令是用户
主动请求，不改变主动通知默认无链接的规则。

## 4. 可选动作链接槽位

Notification Job 的结构化 payload 预留以下可选字段：

```text
action_label: 可选的短标签
action_url: 可选的规范 HTTPS URL
action_source: 可选的来源标识
```

首版 Mikan 资源通知不填写这些字段。未来 B 站视频来源接入后，只有同时满足以下条件
才在通知末尾增加动作区：

- `proactive_action_links_enabled` 已从默认 `false` 明确开启；
- `action_source` 存在于默认只含 `bilibili` 的
  `proactive_action_link_sources` 配置；
- URL 使用 HTTPS；
- URL 是规范的 B 站视频页地址，例如 `https://www.bilibili.com/video/BV...`；
- 每条通知最多一个 URL。

短链接、重定向链接、用户提供的任意 URL、URL 变形文本和无法验证的域名不进入主动
消息。动作链接缺失或校验失败时，整条通知正常发送，只省略动作区。

动作区格式固定：

```text
🎬 相关视频：UP 主更新
https://www.bilibili.com/video/BV...
```

## 5. 模块职责与数据流

- `MikanReleasePipeline` 继续负责资源去重、筛选、聚合和 Notification Job 规划，
  但 payload 改为保存结构化资源摘要，不再把原始标题与 URL 拼成主动通知正文。
- 通知呈现模块负责把结构化摘要压缩为稳定文本，并决定是否渲染动作链接槽位。
- AstrBot renderer 继续负责 `At` 与 `Plain` MessageChain，不解析资源标题或决定
  链接来源。
- 资源详情查询用例负责按群、用户、番剧和集数读取最新安全页面链接。

链接策略集中在通知呈现模块，避免 Worker、命令 adapter 和 AstrBot renderer 各自
实现不同规则。

## 6. 错误处理与兼容

- 字幕组、语言或分辨率缺失时分别显示“字幕组未知”“语言未知”“分辨率未知”；
- 发布时间缺失或无法解析时显示“时间未知”，不使用服务器当前时间代替；
- 旧 Notification Job 仍可通过现有 `text` 字段渲染，避免部署期间丢失已规划任务；
- 新 payload 优先使用结构化摘要；不存在时回退旧文本；
- 动作链接校验失败只记录安全摘要，不记录完整用户消息或敏感参数；
- 不补发因格式升级而已经发送或过期的通知。

## 7. 验收标准

- 资源主动通知正文不含 `http://`、`https://`、Mikan 域名、原始发布标题和 UTC
  ISO 时间；
- 同一通知最多展示 3 行资源规格，重复标签被去除，每行包含对应资源的北京时间
  `MM-DD HH:mm` 发布时间；
- 用户主动执行资源详情命令时最多收到一个安全 Mikan 页面链接；
- 未开启动作链接开关时，即使 payload 带 URL 也不得发送；
- 开关开启后，仅单个规范 B 站视频页 URL 可进入动作区；
- 任意域名、短链接、重定向链接和变形链接均被省略；
- `At` 组件、MessageChain、SendGovernor、Outbox 去重、过期、熔断和安静时段测试
  保持通过；
- 完整自动化和真实测试群 canary 通过后才部署生产。

## 8. 非目标

- 不发送磁力链接、种子直链、私有 RSS、下载地址或自动下载任务；
- 不通过符号替换、二维码、图片文字或短链接规避平台检测；
- 不在本次实现 B 站 UP 主抓取、视频匹配或自动推荐；
- 不改变资源筛选、通知频率和群订阅归属。
