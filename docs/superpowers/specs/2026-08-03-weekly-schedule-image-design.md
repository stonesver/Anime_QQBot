# 本周放送单图呈现设计

## 1. 背景与目标

当前 `本周放送` 使用纯文本列表呈现，虽然保留了日期、时间和集数语义，但在 QQ 群消息中缺少稳定的视觉层级。已确认采用“深夜电台 × 手帐贴纸”的周表视觉方向，并以 C「季节海报」配色作为基线。

本次目标：

- 将 `本周放送` 渲染为一张可直接发送的本地 PNG；
- 按周一至周日分组，突出时间、标题和集数；
- 保留现有纯文本结果作为渲染失败时的完整兜底；
- 不改变查询、时区、NSFW 过滤、排序或数据库模型；
- 暂不修改 `今日番剧` 的呈现。

## 2. 视觉设计

图片使用固定宽度、按条目数量自适应高度的纵向周表：

- 深松石绿渐变背景，顶部保留 `SEASONAL BROADCAST` 标识；
- 标题使用 `本周放送_`，副标题展示周范围与群时区；
- 每个星期显示一个颜色分组标签；
- 每行按“时间 / 标题 / 集数标签”排列；未知时间显示 `待定`；
- 集数标签使用圆角胶囊；已知集数去掉前导零，未知集数不伪造数字；
- 金黄、粉红、薄荷分别承担时间、分组和状态强调，装饰仅使用少量星标；
- 底部展示总条目数和“数据按群时区计算”说明。

图片必须保证在 390px 左右的 QQ 移动端预览宽度下仍可读。标题过长时截断并保留省略号，不能溢出图片边界。

## 3. 模块与数据流

新增 `WeeklyScheduleRenderer`，职责仅为把 `AnimeRow` 列表和群时区转换为本地 PNG。它不查询数据库、不决定业务过滤，也不依赖单番剧封面。

新增 `ScheduleReplyFactory`，接收周表行、`ChatContext`、文本 fallback 和当前时间：

1. 计算当前周一与周日日期；
2. 调用 `WeeklyScheduleRenderer.render_cached()`；
3. 成功时返回只含一个 PNG 的 `Reply`；
4. 渲染异常或缓存不可用时返回传入的 `Reply.from_text(...)`。

`EventAdapter` 增加可选的 `schedule_reply_builder`。只有 `IntentKind.WEEK` 且存在 builder 时走图片构建，其他查询保持原有路径。生命周期在卡片呈现启用且字体可用时同时初始化该 builder；命令适配器把它传入。

缓存目录沿用 `CARD_ASSET_ROOT`，周表放在 `schedules/weekly/` 下。缓存指纹包含周范围、群时区、条目 ID、标题、放送时间和集数，避免不同群或不同周复用错误图片。

## 4. 失败与安全边界

- 字体缺失、Pillow 绘制异常、PNG 写入失败：记录错误类型并回退纯文本；
- 图片路径必须位于 `CARD_ASSET_ROOT` 下，扩展名必须为 `.png`，沿用现有 AstrBot 本地图片校验；
- 不记录消息正文、用户标识或完整图片内容；
- 空结果仍返回现有“本周没有即将放送的番剧”，不生成空图；
- 不引入新的外部网络请求或数据库字段。

## 5. 验证

- `WeeklyScheduleRenderer`：有效 PNG、尺寸上限、星期分组、待定时间、长标题截断、缓存命中；
- `ScheduleReplyFactory`：成功返回单图片、失败返回原文本、空结果不构图；
- `EventAdapter`：周表 builder 接入且今日/季度等场景不受影响；
- 现有 presentation、AstrBot adapter 和 e2e 测试集回归。
