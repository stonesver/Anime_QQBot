# 生产订阅与通知投递修复设计

## 背景

生产环境确认了三项相互独立的问题：

1. AstrBot 固定 `/番剧` 命令的群号可能只存在于 `event.message_obj.group_id`，当前插件
   只读取 `event.group_id`，因此建立了空群及其订阅。
2. 主动通知向 `Context.send_message()` 传入普通 `list`，而 AstrBot 4.26 要求
   `MessageChain`，首次资源提醒因此在平台发送前失败。
3. Mikan 标题中的 `- 01 [1080P]` 未被识别为第 1 集，解析器反而将 `[1080P]`
   识别为第 108 集，产生错误聚合与通知载荷。

## 修复范围

### 群身份

- 固定命令读取群号时与事件规范化层一致：优先 `event.group_id`，缺失时回退到
  `event.message_obj.group_id`。
- `ChatGroupRepository` 拒绝空群号和空用户号，防止其他入口再次写入无效身份。
- 不修改跨群订阅语义；同一用户在不同真实群中的订阅仍相互独立。

### 主动通知

- 开播与资源通知均创建 AstrBot 原生 `MessageChain`。
- 运行时使用 AstrBot 的 `At`、`Plain` 组件；离线测试使用结构相同的轻量替身。
- Dispatcher 只向 `Context.send_message()` 传递消息链对象，不改变任务租约、重试、
  过期或去重语义。

### Mikan 集数

- 支持 `- 01`、`- 01v2` 等常见发布标题格式。
- 方括号集数只接受完整的 1～3 位数字，可带 `v2` 修订标记；`[1080P]` 不再匹配。
- 已持久化的错误批次和失败任务不直接重试，避免发送错误内容。

## 生产数据修复

代码发布并健康后，在事务中：

1. 锁定空群、真实群和目标订阅；
2. 将已确认的空群订阅迁到 QQ 群 `1091724800`；
3. 若真实群已有同一用户、同一番剧订阅则保留真实群记录并删除重复空群记录；
4. 删除无引用的空群成员与空群记录；
5. 将错误的失败通知标记为 `cancelled`，不重试原载荷；
6. 提交后重新查询群、订阅和通知状态。

修复脚本必须按已确认 ID 定位并在执行前后输出只读核对结果，不使用模糊范围删除。

## 验证

- 单元测试覆盖生产形态群事件、空身份拒绝、AstrBot 消息链结构和真实 Mikan 标题。
- 定向运行插件、资源解析和群仓储测试。
- 运行格式化、静态检查、类型检查及完整测试套件。
- 在生产部署后验证容器健康、消费者心跳和真实群中的“我的订阅”结果。
