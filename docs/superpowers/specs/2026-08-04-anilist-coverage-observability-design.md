# AniList 映射覆盖与精确时刻可观测性

## 背景

周表中的同名条目并不一定是重复：渲染层按内部番剧和集数去重；日更番剧在一周内
有多集时，会保留每一集。截图中精确时刻不足的主要原因是未来排期中同时存在：

- 尚未获得严格 AniList 映射的番剧；
- 已映射，但 AniList 当前没有返回未来 `airingAt` 的番剧。

这两类都只能显示日期，不能以猜测的时间替代。

服务器核查发现，截图中的周五「死灵法师！我即是天灾」为同一内部番剧的第 6、7 集，
周六「妖神记 第十季」为第 440、441 集；两组都被 Bangumi 标为同一天的日期精度排期。
这不是两个字幕组或两个内部条目，却会在当前逐集周表中呈现为同日同标题的两张卡。

## 决策

1. 保持现有严格确认门槛：非成人候选、已知标题归一化交集、首播日完全一致且候选唯一。
2. 每次目录同步先处理未来七天尚未映射、且不在重试冷却中的番剧；剩余配额继续按原有
   游标扫描全目录。
3. 对未确认的尝试记录唯一的每番剧 AniList 评估：结论、候选数、最近尝试和下次可重试时间。
   失败冷却 24 小时；确认链接后清除评估记录。
4. 看板将未来排期拆为互斥覆盖指标：精确时刻、已映射但源未给精确时刻、待 AniList 映射。
   映射页同时展示人工待确认链接和严格自动比对未确认的原因。
5. 日表和周表增加展示层第二次去重：同一自然日内同一标准化标题仅显示一张卡，保留
   集数更大的记录；同集竞争时再优先精确时刻。

## 非目标

- 不用模糊标题匹配自动绑定，不为缺时刻的节目推断播出时间。
- 不把一周内不同集数压缩成一行；那会改变周表的逐集语义。
- 不调整 AniList 请求节流和目录同步周期。

## 验收

- 未来七天未映射节目在批处理时先于普通目录项接受严格匹配。
- 无候选或歧义结果在冷却期内不会在每轮同步重复请求。
- 看板能分别显示未来未映射数和已映射但无精确时刻数；两者不再被“待确认映射 0”掩盖。
- 现有已确认映射、手动映射审核和日期精度展示保持兼容。
