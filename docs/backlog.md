# Anime QQBot 待办

本文记录真实群运行中确认的改进项及当前完成状态。未完成项按生产风险和用户体验排序。

群聊触发、发送限频与 AstrBot 内嵌管理面板的详细方案已经确认，见
[群聊交互、发送保护与内嵌管理面板设计](superpowers/specs/2026-07-28-anime-chat-interaction-admin-panel-design.md)。

## 已完成：发送限频与风控保护

v0.3.0 已完成：

- 所有被动回复和主动通知统一进入发送调度器；
- 全局默认每 2～3 秒最多发送一条，突发容量不超过 2；
- 同一用户的命令默认冷却 5 秒；
- 同一群限制短时间内的回复数量，主动提醒之间至少间隔 60 秒；
- 合并相同群、相同番剧和相近时间窗口的通知；
- 保留“发送结果不确定时不自动重试”的现有原则；
- 遇到 QQ 限频、登录验证、强制下线或发送异常时暂停自动发送并记录状态；
- 所有限频参数可配置，默认值面向少量群的保守运行方式；
- 管理页可查看队列数量、失败任务、投递控制和熔断状态。

## P0：QQ 小号登录风险与发布隔离

已完成：

- 应用发布不再固定刷新 PostgreSQL/NapCat vendor 镜像；
- 运行中的 NapCat 在日常应用发布中保持原容器；
- 已停止的 NapCat 不会被日常发布自动唤醒；
- 应用失败回滚不再重建 NapCat；
- vendor 更新通过 `--refresh-vendors` 显式进入维护窗口；
- 发布前后记录 NapCat 容器 ID、启动时间和重启判断；
- QQ 登录卷和 NapCat 配置卷继续独立持久化；
- 运维手册增加异常登录处置和禁止连续扫码重试的流程。

仍需部署者完成：

- ACR 控制台只保留应用 `latest` 自动构建，两个 vendor 规则改成人工触发；
- 在真实服务器升级部署资产并验证一次 `NapCat restart detected: no`；
- 在 QQ 安全中心确认专用小号没有未知设备或未知地点登录。

## P1：群聊交互体验继续优化

v0.3.0 已完成 @入口、安全短命令、短期候选编号、日期参数修复和分层帮助。以下仍待实现：

- 今日、本周和季度结果按日期、星期和时间分组；
- 统一“季度”命令的帮助文本、默认季度行为和实际参数规则；
- 搜索与详情展示中文名、原名、放送状态、评分、简介、下一集和数据来源；
- 在结果后给出可直接复制的下一步操作，例如“回复 1 订阅”；
- “我的订阅”支持编号取消、查看下一集和修改资源偏好；
- 增加队列延迟分位数、限频命中和过期丢弃计数。

## P2：内容呈现与管理体验

v0.3.0 已完成 AstrBot Dashboard 管理员鉴权、群级提醒开关、静默时段、映射审核和
通知控制。以下仍待实现：

- 对长列表分页，避免一次发送过长文本；
- 在安全和平台兼容允许时恢复封面或紧凑卡片展示；
- 在所有者面板提供每日摘要；
- 增加订阅成功后的当前筛选摘要和下一次预计提醒说明；
- 增加真实群 canary、限频压力和通知积压恢复验收。
